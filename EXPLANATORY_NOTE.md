# Пояснительная записка

## Тема проекта

Разработка учебной системы контроля версий MiniGit / COO.code на языке C.

## Цель работы

Цель проекта - реализовать консольную программу, которая демонстрирует основные
принципы систем контроля версий: инициализацию репозитория, хранение снимков
файлов, подготовку изменений, создание коммитов, работу с ветками и возврат к
предыдущим версиям.

## Назначение программы

MiniGit предназначен для локального хранения истории текстовых файлов. Пользователь
может создать репозиторий, добавить файлы в staging area, зафиксировать изменения
коммитом, посмотреть историю, переключиться между ветками или откатиться к
выбранному коммиту.

## Основные возможности

- создание репозитория командой `init [path]`;
- загрузка существующего репозитория командой `load [path]`;
- добавление файлов из рабочей директории командой `add <file>`;
- удаление файлов командой `rm <file>`;
- создание коммитов командой `commit <message>`;
- просмотр статуса, истории и файлов текущего коммита;
- создание и переключение веток;
- простое слияние веток;
- откат текущей ветки и рабочей директории командой `rollback <commit_id>`;
- сохранение состояния репозитория в каталоге `.minigit`;
- поддержка путей с кириллическими символами на Windows.

## Структура проекта

Исходный код расположен в каталоге `src`.

- `main.c` - консольный интерфейс, разбор команд пользователя.
- `core/types.h` - основные структуры данных: blob, tree node, commit, branch, repository.
- `core/tree.c`, `core/tree.h` - работа с деревом файлов и blob-объектами.
- `core/commit.c`, `core/commit.h` - создание коммитов, история, восстановление файлов.
- `core/staging.c`, `core/staging.h` - staging area для подготовленных изменений.
- `core/repo.c`, `core/repo.h` - управление репозиторием, ветками и слиянием.
- `core/repo_storage.c`, `core/repo_storage.h` - сохранение и загрузка `.minigit`.
- `utils.c`, `utils.h` - вспомогательные функции: хеширование, пути, чтение и запись файлов.
- `tests/run_tests.ps1` - автоматические тесты для Windows PowerShell.

## Организация хранения данных

Репозиторий хранится в скрытом каталоге `.minigit` внутри рабочей директории.
В нем размещаются:

- `HEAD` - номер текущего коммита и имя текущей ветки;
- `branches` - соответствие имен веток и коммитов;
- `commits` - метаданные коммитов;
- `objects` - содержимое файлов в виде blob-объектов;
- `trees` - описание дерева файлов для сохраненных состояний.

Каждый коммит содержит идентификатор, сообщение, дату, ссылку на родительский
коммит, список измененных файлов и корень дерева файлов.

## Алгоритм работы

1. Пользователь создает репозиторий командой `init`.
2. Программа создает структуру `.minigit` и начальный коммит.
3. Команда `add` читает файл из рабочей директории и помещает его содержимое в staging.
4. Команда `commit` создает новый снимок дерева файлов и сохраняет его в `.minigit`.
5. Команда `rm` удаляет файл с диска и добавляет удаление в staging.
6. Команда `rollback` находит коммит по ID, восстанавливает файлы из его дерева и
   перемещает текущую ветку на выбранный коммит.

## Тестирование

Для проекта добавлены автоматические тесты PowerShell. Они проверяют:

- сборку программы через GCC;
- создание репозитория в текущей директории и по указанному пути;
- добавление реальных файлов через `add`;
- удаление файлов через `rm`;
- создание коммитов;
- загрузку репозитория после перезапуска;
- откат к предыдущему коммиту;
- базовую работу веток;
- корректную работу с кириллическими путями.

Запуск тестов:

```powershell
powershell -ExecutionPolicy Bypass -File .\tests\run_tests.ps1
```

## Особенности реализации

На Windows для путей с кириллицей используются wide-char функции:
`_wmkdir`, `_wfopen`, `GetFileAttributesW`, `FindFirstFileW` и `FindNextFileW`.
Это нужно, чтобы путь вида `C:\Users\Victor\Desktop\main\шашки` создавался и
читался корректно, без искаженных имен папок.

## Ограничения

MiniGit является учебным проектом. Он не реализует полный набор возможностей Git:
нет полноценного разрешения конфликтов при merge, нет сжатия объектов, нет сетевого
обмена и нет сложной модели индекса. Основная задача проекта - показать базовые
структуры и алгоритмы системы контроля версий.

## Вывод

В результате работы создана консольная система контроля версий, которая позволяет
создавать репозиторий, сохранять версии файлов, удалять файлы, работать с ветками
и возвращаться к предыдущим коммитам. Проект покрыт автотестами и имеет README с
инструкциями по сборке, запуску и использованию.
