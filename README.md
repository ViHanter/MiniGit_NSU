# MiniGit / COO.code

MiniGit - учебная система контроля версий на языке C. Программа хранит историю
файлов в каталоге `.minigit`, поддерживает staging area, коммиты, ветки,
простое слияние, удаление файлов и откат рабочей директории к выбранному
коммиту.

## Возможности

- `init [path]` - создать репозиторий в текущей папке или по указанному пути.
- `add <file>` - прочитать файл из рабочей директории и добавить его в staging.
- `rm <file>` - удалить файл из рабочей директории и подготовить удаление к коммиту.
- `commit <message>` - создать коммит из подготовленных изменений.
- `rollback <commit_id>` - откатить текущую ветку и файлы к выбранному коммиту.
- `status`, `ls`, `cat`, `exists`, `log` - посмотреть состояние репозитория.
- `branch`, `branches`, `checkout`, `merge` - базовая работа с ветками.
- `load [path]`, `close`, `pwd` - загрузка и обслуживание репозитория.

Команда `init-dir <path>` оставлена как совместимый псевдоним для `init <path>`.

## Сборка

Из корня проекта на Windows при установленном GCC:

```powershell
cd src
gcc -I. -Wall -Wextra -o coo.exe main.c core/commit.c core/repo.c core/tree.c core/staging.c core/repo_storage.c utils.c
```

Если в системе установлен `make`, можно собрать из папки `src`:

```sh
make
```

## Запуск

```powershell
cd src
.\coo.exe
```

Пример работы:

```text
init C:\Users\Victor\Desktop\main\шашки
add board.txt
commit "first version"
rm board.txt
commit "remove board"
rollback 2
log
exit
```

## Команды

| Команда | Назначение |
| --- | --- |
| `init [path]` | Создает `.minigit` в текущей папке или по пути `path`. |
| `load [path]` | Загружает существующий репозиторий. |
| `add <file>` | Читает файл из рабочей директории и помещает его в staging. |
| `rm <file>` | Удаляет файл с диска и добавляет удаление в staging, если файл был в коммите. |
| `commit <message>` | Создает новый коммит из staging. |
| `rollback <id>` | Перемещает HEAD и текущую ветку на коммит `id`, восстанавливает файлы. |
| `reset` | Очищает staging без изменения коммитов. |
| `status` | Показывает текущую ветку, коммит и подготовленные изменения. |
| `ls` | Показывает файлы текущего коммита. |
| `cat <file>` | Выводит содержимое файла из текущего коммита. |
| `exists <file>` | Проверяет наличие файла в текущем коммите. |
| `log` | Показывает историю от HEAD к первому коммиту. |
| `branch <name>` | Создает ветку от текущего коммита. |
| `branches` | Показывает список веток. |
| `checkout <branch>` | Переключается на ветку. |
| `merge <branch>` | Выполняет простое слияние выбранной ветки в текущую. |
| `count` | Считает tree/blob объекты в истории. |
| `close` | Закрывает текущий репозиторий. |
| `exit` или `q` | Завершает программу. |

## Автотесты

Тесты собирают программу, создают временные репозитории и проверяют:
инициализацию, добавление файлов, удаление через `rm`, коммиты, загрузку,
откат через `rollback`, ветки, хранение blob-объектов и работу с кириллическими
путями.

```powershell
powershell -ExecutionPolicy Bypass -File .\tests\run_tests.ps1
```

Тесты используют временные папки в системном каталоге `TEMP` и не меняют ваш
реальный пользовательский конфиг.

## Ограничения

Проект является учебным и не заменяет Git. Слияние реализовано упрощенно:
изменения из другой ветки накладываются поверх текущего дерева без полноценного
поиска конфликтов. Пути и метаданные рассчитаны на небольшие учебные примеры.
